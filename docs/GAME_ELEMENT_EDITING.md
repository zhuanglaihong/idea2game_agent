# 游戏元素选择与定向修改

当前产品聚焦 JavaScript、Canvas、Three.js 网页工程。Demo已移除Unity/Godot引擎选择和下载入口。

## 已可体验

1. 点击「选择游戏元素」进入编辑模式；隐藏开始遮罩，暂停游戏模拟，阻止拖动和消牌。
2. 点选画布对象；武侠根据镜头投影坐标识别玩家、飞刀、敌人，三消识别卡牌，Three.js使用Raycaster识别小队和敌人。点击位置显示金色标记，左侧显示稳定目标ID。也可使用目标下拉框。
3. 描述修改：角色颜色、大小、生命；武侠飞刀颜色、大小、数量与转速；敌人颜色与大小；场景色调；卡牌图案大小。Demo通过参数解析执行这些限定修改，并未调用在线LLM。对象ID目前代表同类实体，敌人修改影响敌人类型，不是某一只敌人的独立实例。
4. 作品的elementEdits随本机保存、分享参数和源码导出保留。修改重建试玩实例，当前局进度会重置；退出编辑后可重新开始。

## 正式生成链路

正式AppChatPage新增「选择游戏对象」入口、目标展示和清除。它验证消息来自当前预览iframe，将对象ID和名称附加到真实AI修改请求。HTML、多文件、Vue三个生成提示词都要求生成游戏实现下面的协议。已有旧工程若未实现协议，需要AI补齐后才能点选内部实体；当前没有公网AI后端，因此未做真实模型端到端验收。

父页面发送：
```js
{type:'idea2game:edit-mode',enabled:true}
```
游戏验证event.source===parent，暂停模拟、清除移动输入，并启用命中检测。选择后发送：
```js
parent.postMessage({type:'idea2game:element-selected',element:{id:'player',name:'玩家角色'}},'*');
```
父页面验证event.source是当前iframe窗口，并限制ID和名称长度。游戏应保存稳定ID与实体定义、源文件、属性和素材路径的映射；模型按ID定向修改。Canvas需使用实际绘制/镜头坐标，Three.js需使用Raycaster。DOM菜单继续沿用原网页元素编辑。

## 验证

`npm run test:demo`覆盖原游戏规则、消息来源校验、飞刀参数修改、分享还原和无关对象保持；`npm run build:demo`包含Vue/TypeScript检查。实际浏览器已验证点击角色后生命100→200、飞刀1→3。

联网素材的自动搜索/用户侧导入与外接图片模型实时生成仍为独立待完成项；当前已有联网素材导入脚本和本地素材打包，不应描述为任意资源搜索已经上线。
